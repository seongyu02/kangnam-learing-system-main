# 학습 시스템

**강남대학교 · 네트워크서비스 (2026-2) · 학생 배포용**

처음 사용하는 학생은 **[학생용 사용 가이드](학생용-사용가이드.md)** 를 따라 시작하세요. 팀별 중간고사 범위, Claude Code·Codex 사용법, 모의시험과 오답 복습, 기록 저장 방법을 안내합니다.

---

> **이건 강의 자료 모음이 아니라 시스템입니다.**
> 읽으라고 준 게 아니라 **돌리라고** 준 겁니다. 그리고 이 저장소는 **여러분 겁니다.**

---

## 1. 이걸로 뭘 하나

1주차에 배운 다섯 전략 — 인출 연습 · 간격 반복 · 인터리빙 · 청킹 · 정교화 — 이
여기서는 **말이 아니라 실행되는 절차**로 들어 있습니다.

`/study` 라고 치면 AI가 **여러분에게 질문을 시작합니다.** 답을 주는 게 아니라요.
여러분이 답하면 채점하고, 틀린 건 복습큐에 쌓입니다. 다음에 켤 때 그게 다시 나옵니다.

## 2. 5분 안에 시작하기

### ① 내 GitHub에 올린다

압축을 풀고, **한글과 공백이 없는 경로**에 두세요.

```
macOS     ~/dev/netsvc
Windows   C:\dev\netsvc
```

```bash
cd ~/dev/netsvc
git init
git add -A
git commit -m "학습 시스템 시작"
```

그리고 GitHub에서 **비공개(Private) 저장소**를 새로 만들고 연결합니다.

```bash
git remote add origin https://github.com/{내아이디}/{저장소이름}.git
git branch -M main
git push -u origin main
```

> **왜 올리나** — 학기 끝까지 여기에 뭐가 쌓였는지가 여러분의 제출물입니다.
> 노트북이 죽어도 살아남아야 하고, 언제 무엇을 했는지가 커밋에 남습니다.

### ② Claude Code 또는 Codex를 켠다

```bash
cd ~/dev/netsvc
claude
```

Codex 앱에서는 이 저장소 폴더를 프로젝트로 열고 **새 대화**를 시작하세요.
Codex CLI를 사용하는 경우 저장소 폴더에서 `codex`를 실행합니다.

```bash
cd ~/dev/netsvc
codex
```

### ③ 첫 명령

```
/study 작년에 들은 전공 과목 중 아무거나 하나
```

Codex에서는 `/` 대신 `$`로 스킬을 호출합니다.

```text
$study 작년에 들은 전공 과목 중 아무거나 하나
```

| 학습 | Claude Code | Codex |
|---|---|---|
| 주제·로드맵 학습 | `/study DB 설계 Phase 2` | `$study DB 설계 Phase 2` |
| 중간고사 1단계 | `/midterm-concept 01` | `$midterm-concept 01` |
| 중간고사 2단계 | `/midterm-prompt 02` | `$midterm-prompt 02` |
| 오답 다시 풀기 | `/midterm-concept 02 오답` | `$midterm-concept 02 오답` |

"DB 설계 Phase 2 공부하자", "02팀 중간고사 모의시험 보자"처럼 말해도 됩니다.
두 도구는 같은 문제은행과 `내학습/` 기록을 사용하므로 이전 진도를 이어갈 수 있습니다.
같은 기록 파일을 두 도구에서 동시에 수정하지 마세요.
스킬이 보이지 않으면 저장소 루트가 프로젝트로 열려 있는지 확인하고 새 대화를 시작하세요.

**모르는 주제로 시작하지 마세요.** 첫 바퀴는 **이미 배운 것**으로 돕니다.
이유는 아래 5번에 있습니다.

## 3. 스킬

|---|---|---|
| **`/study <주제>`** | AI가 질문하고, 내가 답하고, 틀린 게 복습큐에 쌓인다 | 매일 |
| **`/study <로드맵>`** | 같은 명령입니다. **로드맵 이름을 주면** 그 진도를 순서대로 나갑니다 | 진도 나갈 때 |

| **`/midterm-prompt 01`** · **`/midterm-prompt 02`** | 중간고사 모의 **2단계**. 팀별 15문제. 그 개념으로 AI에게 요청문을 쓰고, AI 결과를 검수하고, AI와 사람의 몫을 가른다 | 1단계 뒤 |

> `/study` 하나가 둘을 다 합니다. **주제를 말하면 그 주제로 시험을 보고,
> 로드맵이나 Phase 이름을 말하면 그 자료를 순서대로 통과시킵니다.**

## 5. 읽고 시작하기 전에 — 이게 제일 중요합니다

1주차 마지막에 이런 말을 했습니다.

> **정교화는 재료가 없으면 작동하지 않고, AI는 재료 없이도 답을 줍니다.**

모르는 주제에 "왜?"를 던지면, 사람은 침묵하지 않고 **소설을 씁니다.**
그리고 **AI는 그 소설을 아주 매끄러운 문장으로 대신 써 줍니다.**
읽으면 이해한 것 같습니다. 그게 유창성의 착각입니다.

그래서 이 시스템의 스킬은 **답을 먼저 주지 않게** 만들어져 있습니다.
질문부터 하고, 여러분이 답한 뒤에만 채점합니다. 불편하면 제대로 작동하고 있는 겁니다.

**첫 바퀴를 이미 아는 과목으로 도는 이유도 같습니다.**
AI가 틀린 말을 유창하게 할 때, 그걸 잡아낼 수 있는 건 그 주제를 아는 사람뿐입니다.
아는 과목에서 AI가 틀리는 걸 한 번 잡아 봐야, 모르는 과목에서 조심하게 됩니다.

## 6. 매주 하는 것

1. `/study` 로 한 판 돈다
2. 틀린 게 `내학습/복습큐.md` 에 쌓인다
3. 커밋하고 푸시한다

```bash
git add -A && git commit -m "학습: {오늘 한 것}" && git push
```

12주 동안 한 줄도 안 쌓였다면, 이 시스템을 안 쓴 겁니다.
