### DB Phase 3 — 학습한 핵심과 보완

- 슈퍼키·후보키: 직원번호만으로 유일하게 구별할 수 있으므로 직원번호+이름에는 불필요한 이름이 있음. 처음 후보키로 답한 뒤 교정. 직원번호 단독은 후보키라고 설명.
- 기본키·대체키: 기본키로 선택하지 않은 후보키인 회사 이메일을 대체키로 맞힘.
- 복합키: 수강 기록에 과목번호+성적을 제안했다가, 성적 중복 반례로 교정. 학번+과목번호가 함께 필요하고, 성적을 더 붙인 조합은 불필요한 속성이 있는 슈퍼키라고 설명.
- 외래키·참조 무결성: C99가 고유하다는 이유만으로 주문 저장이 가능하다고 판단했다가, 참조 대상 고객 행이 먼저 존재해야 함을 설명으로 학습. 이후 존재하지 않는 과목을 참조하는 수강은 외래키 제약으로 거부된다고 맞힘. 조회는 과목명이 아니라 과목ID 기준이라는 용어를 보완.
- 참조 대상 삭제: 주문이 참조하는 고객의 삭제는 지정된 삭제 거부 규칙 때문에 불가하다고 설명. 주문 없는 고객 등록은 가능하다고 답했고, 테이블 분리 자체가 아니라 제약 방향 때문이라는 이유를 보완.
- 자연키·대리키: 이메일 대신 변경되지 않는 사용자 ID를 기본키로 선택한다고 근거까지 설명.
- 1:N 변환: 과목 테이블에 프로그램ID 외래키를 추가한다고 맞힘.
- N:M 변환: 수강 테이블에 학생ID·과목ID 외래키를 넣는 것은 맞혔으나 학생ID 단독 기본키를 제안함. 복합 기본키 하나가 두 속성으로 구성됨을 설명한 뒤, 같은 학생·같은 과목 조합의 중복은 거부된다고 맞힘.
- 자기 참조: 상사를 별도 테이블로 가정한 답을 같은 직원 테이블 참조 조건에 맞춰 보완. 상사ID는 같은 테이블의 직원ID를 참조하며, 한 상사는 여러 직원을 관리할 수 있어 반복 가능함을 학습.
- NULL: 상사가 없는 직원 허용 시 상사ID에 NOT NULL을 걸면 안 된다고 설명. 모듈 없음과 미분류를 같은 NULL로 표현하면 미분류 강의를 모듈 없는 강의로 잘못 집계한다고 설명.

### DB Phase 4 — 현재까지 확인한 내용

- 함수 종속 X→Y: 두 행의 X 값이 같으면 Y 값도 같아야 함. 같은 B에 다른 A는 B→A 위반, 서로 다른 B에 같은 A는 허용됨을 확인.
- 현재 데이터와 업무 규칙: 지금 이름이 모두 달라도 동명이인이 가능하므로 이름→학번을 일반 규칙으로 확정할 수 없다고 설명.
- 완전·부분 종속: 복합키 일부만으로 결정하면 부분 종속, 전체가 필요하면 완전 종속. 처음에는 중복 여부로 이유를 설명하거나 성적을 부분 종속으로 판정했다가 교정. 이후 상품번호만으로 상품명이 결정되므로 복합키에 부분 종속이라고 근거까지 설명.
- 이행 종속: 직원번호→부서번호→부서명을 연결함.
- 폐포: 집합에는 속성 이름을 각각 적고, 순서는 무관하며 중복은 한 번만 적음. 처음 속성 자체를 포함하고, 결정자의 모든 속성을 확보한 규칙만 적용함.
- 기호·표현: 학생은 기호와 용어가 처음이라 충분한 설명이 필요하다고 요청함. 순서 변경, 중복 정리, (C,E)의 공동 결정과 집합 원소 구별은 설명 부족을 보완한 것이며 그 자체를 새 오답으로 기록하지 않음.
- 10/14 독립 계산 결과: C⁺={C,A}; (C,E)⁺={C,E,D,A}; D→B 추가 후 (C,E)⁺={C,E,D,A,B}; E⁺={E}.
- 후보키 확인: (C,E)는 모든 속성을 결정하고 C 또는 E를 빼면 전체를 결정하지 못함. 슈퍼키라고 답한 것은 참이지만 후보키 여부 설명이 부족해 포함 관계를 보완함. 이후 (C,E,A)는 A가 불필요한 슈퍼키이고 A를 빼면 후보키라고 답함.
- 1NF는 정의와 첫 문제만 제시함. 아직 학생의 답을 받지 않았으며 1NF·2NF·3NF·BCNF 학습 완료로 처리하지 않음.

- 처음 보는 용어·기호는 뜻과 사용법부터 설명한다. 새 개념은 설명 → 풀이 예제 → 학생이 직접 답하는 문제 하나로 진행한다.
- 표현을 통일한다: “폐포를 계산한다”. 설명 없이 “출발”, “구한다” 등으로 바꿔 쓰지 않는다.
- 익숙한 기초는 반복을 줄이되 필수 설명은 생략하지 않는다. 원문 사례와 변형 사례를 구분한다.
- 기록은 학습을 마칠 때 모아서 저장한다. 이번 기록은 파일 저장까지 수행하며, 새 커밋·푸시는 수행하지 않았다.
- Phase 3·4 전체 실습 및 전체 Phase는 미완료다. 강의 핵심 확인과 전체 산출물 완료를 구분한다.
- 이번 마무리의 학생 세 줄 요약은 아직 받지 않았다.

### 2026-10-15 확인 결과

‘확인’에는 처음부터 맞힌 항목과 교정 후 다른 사례를 직접 맞힌 항목이 포함된다. ‘보완’은 설명·힌트 후의 짧은 답만 받았거나, 근거 재확인·독립 적용·미응답 문항이 남은 항목이다. 보완 8항목을 모두 오답 8문항으로 계산하지 않는다.

| # | 핵심 항목 | 최종 상태 | 실제 응답과 보완 사항 |
|---|---|---|---|
| 1 | 복합 기본키 | 보완 | 학생ID만 알면 강좌가 결정된다고 답해 오답. 한 학생의 여러 강좌 사례로 교정한 뒤 동일한 학생ID·강좌ID 행의 재저장은 불가하다고 맞힘. 처음 이해와 교정 후 응답을 구별하고 다음 날 새 사례로 재확인 |
| 2 | 외래키 참조 대상 존재 | 확인 | C99는 강좌 테이블에 없으므로 참여 저장이 불가하다고 독립 답변. ‘없는 테이블’이라는 표현을 ‘없는 강좌 행’으로 보완 |
| 3 | 완전·부분 종속 | 교정 후 확인 | 학생이름을 완전 종속이라고 답했다가 교정. 이후 주문일자는 주문번호만으로 결정되므로 복합키에 부분 종속이라고 새 사례를 근거까지 맞힘 |
| 4 | 1NF | 확인 | 한 칸에 강좌ID 두 개가 들어 있어 1NF 위반이라고 설명 |
| 5 | 2NF 분해 | 교정 후 확인 | 성적을 분리한다고 답했다가 부분 종속 속성을 분리하는 원칙을 보완. 이후 상품(상품번호, 상품명), 주문상세(주문번호, 상품번호, 주문수량)로 새 사례를 직접 정확히 분리 |
| 6 | 3NF 분해·종속 유형 | 확인 | 직원(직원번호, 부서번호), 부서(부서번호, 부서명)로 직접 분리. 2NF는 부분 종속, 3NF는 이행 종속 제거라고 구별. 부서명 변경 시 10행/1행 수정과 옛 이름 잔류는 단계별 힌트 후 답함 |
| 7 | BCNF | 교정 후 확인 | 결정자는 슈퍼키라고 기억함. C⁺={C,B}가 전체 A,B,C를 포함하지 않는데 위반이 아니라고 답해 교정. 새 사례에서 B⁺={B,A,C}, B가 슈퍼키라 위반이 아니라고 계산·판정 모두 맞힘 |
| 8 | 무손실 분해 | 확인 | 동명이인을 이름으로 연결해 원래 없던 수강 기록이 생기는 분해는 무손실이 아니라고 설명 |
| 9 | 종속성 보존 | 보완 | 같은 학생·같은 과목이라는 문장을 구체적인 S01·C01 값으로 설명한 뒤 강사 두 명은 한 명 규칙을 지키지 못한다고 답함. 분해 후 개별 제약과 원래 규칙의 관계는 새 사례로 재확인 필요 |
| 10 | 4NF의 독립 목록 분리 | 확인 | 학생ID·취미 / 학생ID·사용언어 두 테이블로 직접 정확히 분리 |
| 11 | 조인·비정규화 판단 | 보완 | 조인이 낯설다고 해 고객번호로 이름을 조회 결과에 붙이는 과정을 설명. 복사한 이름에는 김민수가 남고 조인 재조회에는 김지수가 나온다고 맞힘. 성능 측정·동기화·불일치 검출을 스스로 묶어 판단한 답은 아직 없음 |
| 12 | 관계 자체의 속성 위치 | 보완 | 역할은 강좌마다 바뀌므로 강좌 테이블에 둔다고 답해 교정. 같은 C01에서도 S01은 학생, S02는 교사라는 사례를 제시. 후속 답은 ‘강좌마다 역할이 다르다’여서 같은 강좌 내 사람별 차이에 대한 근거 재확인 필요. 사용자 요청으로 다음 주제로 이동 |
| 13 | 반복 학습 사건과 기본키 | 보완·미응답 포함 | 복습마다 행 추가라고 답함. 학습일도 필요하다는 점을 설명. 학생ID·강의ID만 기본키면 반복 기록 불가, 학습일까지 포함하면 다른 날짜 기록은 구별한다고 맞힘. 같은 날 오전·오후 두 학습을 날짜만 있는 복합키로 저장할 수 있는지는 건너뜀 |
