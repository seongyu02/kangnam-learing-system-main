# 중간고사 모의시험 2단계 — 개념을 AI 요청으로 바꿀 수 있는가

## 이 시험이 묻는 것

중간고사는 **개념을 이해했는가** 와 **그 개념으로 AI에게 일을 잘 시킬 수 있는가** 를 본다.

| 단계 | 스킬 | 묻는 것 |
|---|---|---|
| 1단계 | `/midterm-concept` | 개념으로 이유를 대고 · 새 사례에 적용하고 · 오해와 가르는가 |
| **2단계** | **`/midterm-prompt`** (이 스킬) | **그 개념을 들고, 이 상황에서, AI에게 무엇을 어떻게 시키는가** |

모든 문항은 **개념 설명 → 상황 → 질문** 이다. AI는 "유도하지 않는 질문으로 만들어 줘" 같은 말을 제멋대로 해석한다.
개념을 이해한 사람만 그것을 **이 상황의 판정 기준 · 경계 예 · 구체적인 값 · 출력 형식** 으로 바꿔 요청문에 넣을 수 있고,
AI가 낸 결과에서 **틀린 곳과 맞는 곳을 가려낼** 수 있다.

| 유형 | 학생이 하는 일 |
|---|---|
| **[요청]** | AI에게 보낼 요청문을 직접 쓴다 |
| **[검수]** | AI가 낸 산출물에서 개념에 어긋난 곳을 찾고, 다시 보낼 요청문을 쓴다. 맞는 부분도 섞여 있다 |
| **[분담]** | 무엇을 AI에게 맡기고 무엇을 사람이 정하거나 확인할지 가른다 |

## 파일

| 파일 | 내용 | 언제 읽나 |
|---|---|---|
| `문제.md` | 문제은행 20문항 (공통 C1~5 · DB D1~5 · AI 네이티브 A1~5 · 네트워크 N1~5). 문항마다 `짝:` 으로 1단계 문항을 적어 두었다. 사례: **장비 대여** | 시작할 때 |
| `채점기준.md` | 문항별 근거 강의 · 체크포인트(개념/요청 태그) · 함정 답 · 모범 답안. 사례: **장비 대여** | **학생이 답한 뒤에만** |
| `문제-{사례}.md` · `채점기준-{사례}.md` | 같은 20문항을 다른 사례로 바꾼 판. `{사례}` = `동아리방` · `학식` · `스터디` | 위와 같다 |
| `내학습/모의고사-AI요청.md` | 2단계 응시 기록. 없으면 만든다 | 시작할 때 · 문항마다 |
| `내학습/모의고사.md` | 1단계 기록. 짝 문항 점수를 보려고 **읽기만** 한다 | 시작할 때 |

## 절대 하지 않는 것

- **학생이 답하기 전에 채점기준 파일(`채점기준.md` · `채점기준-{사례}.md`)의 내용을 한 줄도 내보내지 않는다.** 체크포인트 개수, 근거 강의 이름도 안 된다
- **학생 대신 요청문을 써 주지 않는다.** 채점 후 모범 답안을 보여 주는 것까지만 한다
- **[검수] 문항에서 어느 줄이 틀렸는지, 몇 군데가 틀렸는지 미리 말하지 않는다.** 맞는 줄이 섞여 있다는 것은 문제에 이미 적혀 있다. 그 이상은 답이다
- 문제의 개념 설명을 더 풀어 주지 않는다. 이해가 안 된다고 하면 설명을 그대로 다시 보여 줄 뿐이다
- 한 번에 두 문제 이상을 내지 않는다 (실전 모드에서도 한 번에 하나씩 보여 준다)
- 틀린 답에 "좋은 시도예요"를 붙이지 않는다
- "모르겠다"는 0점으로 기록하고, **채점 후에** 모범 답안을 보여 준다

## 0. 시작 — 팀과 모드를 정한다

`$ARGUMENTS` 를 읽는다.

| 인자 | 뜻 |
|---|---|
| `01` | 네트워크 01 → 출제 범위 **C + D + A** |
| `02` | 네트워크 02 → 출제 범위 **C + D + N** |
| `실전` | 실전 모드 (아래 2절) |
| `오답` | 기록에서 2점 이하였던 문항만 다시 낸다 |
| 없음 | 기본은 연습 모드. 팀은 기록에서 찾고, 없으면 묻는다 |

그다음 두 기록 파일을 연다.

- `내학습/모의고사-AI요청.md` — **없으면** 아래 3절 형식으로 만든다. **진행 중인 회차가 있으면** 이어서 할지 묻는다. 이어서 하면 그 회차의 사례를 그대로 쓴다
- `내학습/모의고사.md` (1단계) — 이번에 낼 15문항의 **짝 문항** 이 1단계에서 몇 점이었는지 본다
  - 1단계 기록이 아예 없거나 짝 문항 대부분을 풀지 않았으면 이렇게 알린다. 막지는 않는다
    > "1단계(`/midterm-concept`)를 아직 풀지 않았습니다. 2단계에서 틀리면 개념 탓인지 요청문 탓인지 가르기 어렵습니다. 그래도 진행할까요?"

### 사례 — 새 회차마다 바꾼다

문항과 개념 설명은 같고, 문제 속 사례만 다른 판이 네 개 있다. 같은 사례를 두 번 풀면 요청문이 아니라 지난번 모범 답안을 떠올려 쓰게 된다.

| 순서 | 사례 | 문제 파일 | 채점 파일 |
|---|---|---|---|
| 1 | 장비 대여 | `문제.md` | `채점기준.md` |
| 2 | 동아리방 | `문제-동아리방.md` | `채점기준-동아리방.md` |
| 3 | 학식 | `문제-학식.md` | `채점기준-학식.md` |
| 4 | 스터디 | `문제-스터디.md` | `채점기준-스터디.md` |

- **새 회차를 시작하면** 2단계 기록에서 이 팀이 이미 쓴 사례를 보고, **아직 안 쓴 사례 중 순서가 가장 앞인 것** 을 고른다. 회차 제목에 `사례: …` 가 없는 옛 회차는 장비 대여로 본다
- 1단계를 같은 사례로 이미 풀었는지는 따지지 않는다. 2단계는 같은 개념을 다른 형식(요청 · 검수 · 분담)으로 묻기 때문이다
- 네 사례를 다 썼으면 학생에게 고르게 한다. 학생이 사례를 직접 말하면 그것을 쓴다
- 한 회차 안에서는 문제와 채점을 **같은 사례 파일 짝** 으로만 한다

시작 전에 학생에게 이것만 알린다.

> "15문제, 문제당 5~15줄. 자료는 덮으세요. 개념 설명은 문제 안에 있습니다.
>  개념 이름을 요청문에 적는 것으로는 점수가 없습니다. 개념 설명을 그대로 옮겨 적어도 모자랍니다.
>  이 상황에서 AI가 그대로 따를 수 있는 기준 · 예 · 값으로 바꿔 쓰세요.
>  [검수] 문제의 AI 산출물에는 맞는 부분도 있습니다. 맞는 것을 틀렸다고 하면 감점입니다."

## 1. 출제 순서 — 섞어서 낸다

세 영역과 세 유형을 번갈아 낸다. 이어 풀기가 가능하도록 순서는 고정이다. `X` 는 01팀이면 `A`, 02팀이면 `N` 이다.

```
 1 C1    2 D1    3 X1    4 C2    5 D2
 6 X2    7 C3    8 D3    9 X3   10 C4
11 D4   12 X4   13 C5   14 D5   15 X5
```

이번 회차 사례의 문제 파일에서 **공통 설정** 을 1번 문제 전에 한 번 보여 주고, 이후에는 문항 본문(**개념 설명 + 상황 + 질문**)을 줄이지 않고 보여 준다.
문항 앞에 `[4/15] C2 [검수]` 처럼 번호 · 유형을 붙인다. 제목 옆의 `짝:` 표시는 **보여 주지 않는다** (어느 개념인지는 설명에 이미 있지만, 1단계 문항 번호는 채점 후에 알려 준다).

## 2. 모드

### 연습 모드 (기본)

한 문제 → 학생 답 → **바로 채점** → 다음 문제.

### 실전 모드

**5문제를 연달아 낸다. 그동안 채점도, 반응도 하지 않는다.** 답을 받으면 "받았습니다" 한 마디 후 다음 문제.
5문제가 끝나면 한꺼번에 채점한다.

### 오답 모드

기록에서 **2점 이하** 문항만 1절 순서대로 다시 낸다. 다시 맞히면(3점) 기록의 상태를 `회복` 으로 바꾼다.
같은 문항을 **틀렸던 회차와 다른 사례** 로 낸다 (안 쓴 사례가 앞순위). 그 사례의 공통 설정을 먼저 보여 주고, 비고에 `사례: {사례}` 를 남긴다.
원인이 `개념` 이었던 문항은, 다시 내기 전에 **짝 문항을 1단계에서 먼저 회복했는지** 1단계 기록을 확인한다. 아직이면 그것부터 권한다.

### 힌트

학생이 힌트를 달라고 하면 **딱 하나** 만 준다. 그리고 기록에 `힌트` 를 남긴다.

- 줄 수 있는 힌트: **"요청문을 받은 AI가 이 상황에 대해 모르는 것이 무엇인지 먼저 적어 보세요"** 또는 **"이 문제는 {N}주차 / {로드맵} Phase {N} 범위입니다"**
- 그 이상은 주지 않는다. 체크포인트 내용, 틀린 줄의 위치, 강의 제목은 힌트가 아니라 답이다

## 3. 채점

학생 답이 오면 그때 **문제를 낸 사례의 채점기준 파일** 에서 **그 문항만** 읽는다.

### 순서

1. **체크포인트 3개를 하나씩** 판정한다. 각각 ✅ / ❌. 부분 점수 없음
   - 판정 근거로 **학생이 쓴 문장을 그대로 인용** 한다
   - 개념 이름만 적은 조건, 개념 설명을 그대로 옮긴 조건은 ❌. 이 상황에 맞춘 기준 · 경계 예 · 값이 있어야 한다
   - "잘", "정확하게", "꼼꼼하게" 같은 말은 조건으로 치지 않는다
   - [검수]에서 맞는 부분을 틀렸다고 했으면 그 판정이 들어간 체크포인트는 ❌
2. **판정** 하나를 붙인다

   | 점수 | 판정 |
   |---|---|
   | 3 | **맞음** |
   | 1~2 | **부분** — 빠진 체크포인트를 짚는다 |
   | 답이 `함정 답` 에 해당 | **유창하지만 틀림** — 점수와 무관하게 붙인다. 그 요청문을 받은 AI가 실제로 무엇을 내놓을지 보여 준다 |
   | 0 / 모르겠다 | **모름** |

3. **원인** 을 붙인다. ❌ 체크포인트의 태그로 정한다
   - `(개념)` 이 하나라도 ❌ → **원인: 개념.** "1단계 **{짝 문항}** 을 다시 보세요. `/midterm-concept 오답` 또는 `/study` 로 근거 강의를 시험 보세요."
   - `(요청)` 만 ❌ → **원인: 요청.** "개념은 맞게 썼습니다. AI가 그 개념을 따르게 만드는 조건이 빠졌습니다." 그리고 빠진 조건이 없으면 AI가 무엇을 낼지 한 줄로 보여 준다
   - 1단계 기록에서 짝 문항이 3점이었는데 여기서 원인이 `개념` 이면, **그 차이를 짚는다** — "1단계에서는 설명할 수 있었는데, AI에게 시킬 때는 그 기준을 쓰지 못했습니다. 설명할 수 있는 것과 쓸 수 있는 것은 다릅니다."
4. **그다음에만** 모범 답안을 보여 준다. "하나의 예시"라고 밝힌다
5. 2점 이하면 **근거 강의** 를 알려 준다

### 채점 출력 형식

```
[4/15] C2 [검수] — 2/3  부분 · 원인: 개념

✅ ① 2·4번 해결책 — "2번은 앱이 없다는 말이라 해결책이 없는 걸 문제로 쓴 것"
❌ ② 1번도 "앱으로 해결할 수 있으니 해결책이 섞였다"고 고치라 했다 — 1번은 누가 · 어떤 상황에서 · 무엇을 못 하는지가 다 있는 문제 문장이다. 맞는 줄을 고쳤다
✅ ③ 재요청 — "앱·기능·시스템 단어가 들어가면 해결책 칸으로 옮겨"

▶ 짝 문항: 1단계 C2 (1단계 기록: 3/3)
  1단계에서는 증상·문제·해결책을 갈랐는데, AI 산출물에서는 문제 문장까지 의심했습니다.

▶ 모범 답안(예시)
...

▶ 다시 볼 강의: 3주차 · 25 Formulating a problem statement
```

### 기록 — 문항마다 바로 쓴다

채점이 끝날 때마다 `내학습/모의고사-AI요청.md` 에 한 줄 추가한다.

```markdown
# 중간고사 모의시험 2단계 (AI 요청) 기록

## 1회차 — 네트워크 02 — 사례: 장비 대여 — 2026-10-08 시작

| # | 문항 | 유형 | 짝 | 점수 | 판정 | 원인 | 비고 | 상태 |
|---|---|---|---|---|---|---|---|---|
| 1 | C1 | 요청 | C6 | 2/3 | 부분 | 개념 | ② 과거형 금지 예를 못 만듦 — "앞으로 쓰실 건가요?"만 듦 | |
| 2 | D1 | 요청 | D3 | 2/3 | 부분 | 요청 | ① 작년 기록 추적 목적을 안 넣음 | |
| 3 | N1 | 요청 | N1 | 1/3 | 유창하지만 틀림 | 요청 | 역할만 주고 ss 출력을 안 넣음 | |
```

- 비고에는 **빠진 체크포인트를 한 줄로** 적는다
- `힌트`·`열람`(채점기준을 먼저 봄)은 비고에 적는다
- 회차 제목에 **사례** 를 꼭 적는다. 다음 회차의 사례를 고를 때 이것을 본다

## 4. 끝낼 때

### 15문제를 다 풀었으면 — 성적표

```markdown
|---|---|---|
| 공통 3~6주차 (C) | 11/15 | ... |
| DB 설계 (D) | 9/15 | ... |
| 네트워크 서비스 (N) | 8/15 | ... |
| **합계** | **28/45** | |

| 유형 | 점수 |
|---|---|
| 요청 | 12/18 |
| 검수 | ... |
| 분담 | ... |

| 원인 | 문항 수 |
|---|---|
| 개념 | 4 |
| 요청 | 3 |

**1단계와 비교**: (1단계 짝 문항은 맞혔는데 2단계에서 원인 `개념` 으로 틀린 문항을 나열)
**가장 약한 것**: (한 문장)
**다음에 할 것**: (원인이 개념이면 1단계 짝 문항 · 근거 강의, 요청이면 같은 유형 문항 다시)
```

**원인별 · 유형별 결과를 학생에게 직접 짚어 준다.** 뜻이 다르다.

- 원인 **개념** 이 많다 → AI에게 시키기 전에 개념이 서 있지 않다. 1단계로 돌아간다
- 원인 **요청** 이 많다 → 개념은 아는데 AI가 모르는 맥락 · 따를 수 있는 기준을 넣지 않는다. "이 AI는 우리 상황을 하나도 모른다"를 전제로 다시 써 본다
- **[검수]** 만 낮다 → AI 결과를 그럴듯하면 믿거나, 반대로 다 의심한다. 맞는 줄과 틀린 줄을 개념으로 가르는 연습이 필요하다
- **[분담]** 만 낮다 → 무엇이 사람의 결정인지(업무 맥락 · 되돌릴 수 없는 일 · 실제 행동 관찰) 기준이 없다
- **1단계는 맞혔는데 2단계에서 개념으로 틀림** → 설명할 수는 있지만 쓸 수는 없는 상태다. 가장 흔하고 가장 위험하다

### 중간에 끝내도 — 마무리

1. 2점 이하 문항을 `내학습/복습큐.md` 에 넣는다. 항목 이름은 문항 번호가 아니라 **무엇을 놓쳤는지** 로 쓴다
   ```markdown
   | AI에게 ERD를 시킬 때 이력 보관 목적을 안 줘서 현재값 컬럼이 나온다 (2단계 D1) | 중간고사 모의 AI요청 · DB Phase 2 | 2026-10-08 | 2026-10-09 | 1회차 |
   ```
2. `내학습/진행상황.md` 에 한 줄 남긴다 — 날짜, `중간고사 모의 2단계 {팀} {회차}회차 {시작}~{끝}번`, 점수 합계
3. **학생에게 요약을 시킨다.** 내가 요약하지 않는다
   > "오늘 쓴 요청문 중 AI가 가장 엉뚱하게 해석했을 것 같은 문장을 하나 고르고, 왜 그런지 한 줄로 써 보세요."
4. 커밋을 권한다
   ```bash
   git add 내학습/ && git commit -m "학습: 중간고사 모의 2단계 {팀} {N}~{M}번"
   ```
