# 중간고사 모의시험 1단계 — 설명을 읽은 다음에 쓸 수 있는가

## 이 시험이 묻는 것

중간고사는 **개념을 이해했는가** 와 **그 개념으로 AI에게 일을 잘 시킬 수 있는가** 를 본다.

| 단계 | 스킬 | 묻는 것 |
|---|---|---|
| **1단계** | **`/midterm-concept`** (이 스킬) | 개념으로 이유를 대고 · 새 사례에 적용하고 · 오해와 가르는가 |
| 2단계 | `/midterm-prompt` | 그 개념을 들고, 이 상황에서, AI에게 무엇을 어떻게 시키는가 |

AI에게 시키려면 개념이 먼저 서 있어야 한다. 이 스킬은 그 바닥을 다진다.

모든 문항은 **개념 설명 → 서술형 질문** 이다. 개념의 이름과 정의는 문제가 먼저 준다.
그래서 정의를 외웠는지는 묻지 않는다. 묻는 것은 그다음이다.

> **설명을 읽고 끝나는 게 아니라, 그 개념으로 이유를 대고 · 새 사례에 적용하고 · 오해와 가를 수 있는가.**

읽어서 익숙해진 느낌은 이해가 아니다. 설명을 그대로 옮겨 적으면 점수가 없고,
설명에 **없던 것** — 이유, 사례에 대한 판정, 결과, 반례 — 을 써야 점수가 난다. 문제는 세 유형이다.

| 유형 | 학생이 하는 일 |
|---|---|
| **[이유]** | 왜 그런지, 그 원칙을 어기면 무엇이 깨지는지 서술한다 |
| **[적용]** | 처음 보는 사례에 개념을 대어 판정하고 계산한다 |
| **[구별]** | 비슷해 보이는 것, 그럴듯한 오해와 개념을 가른다 |

## 파일

| 파일 | 내용 | 언제 읽나 |
|---|---|---|
| `문제.md` | 문제은행 40문항 (공통 C1~10 · DB D1~10 · AI 네이티브 A1~10 · 네트워크 N1~10). 사례: **장비 대여** | 시작할 때 |
| `채점기준.md` | 문항별 근거 강의 · 체크포인트 · 함정 답 · 모범 답안. 사례: **장비 대여** | **학생이 답한 뒤에만** |
| `문제-{사례}.md` · `채점기준-{사례}.md` | 같은 40문항을 다른 사례로 바꾼 판. `{사례}` = `동아리방` · `학식` · `스터디` | 위와 같다 |
| `내학습/모의고사.md` | 응시 기록. 없으면 만든다 | 시작할 때 · 문항마다 |

## 절대 하지 않는 것

- **학생이 답하기 전에 채점기준 파일(`채점기준.md` · `채점기준-{사례}.md`)의 내용을 한 줄도 내보내지 않는다.** 체크포인트 개수, 근거 강의 이름도 안 된다. 근거 강의 이름이 곧 힌트다
- 문제를 바꿔 말하면서 답의 방향을 흘리지 않는다 ("혹시 ~ 관점에서 보면요?" 금지)
- **문제의 개념 설명을 더 풀어 주지 않는다.** 설명이 이해가 안 된다고 하면 설명을 그대로 다시 보여 줄 뿐이다. 덧붙인 설명은 곧 답이다
- 한 번에 두 문제 이상을 내지 않는다 (실전 모드에서도 한 번에 하나씩 보여 준다)
- 틀린 답에 "좋은 시도예요"를 붙이지 않는다
- 학생이 "모르겠다"고 하면 답을 알려 주지 않는다. 0점으로 기록하고, **채점 후에** 모범 답안을 보여 준다
- 학생 대신 답을 써 주지 않는다. 채점 후 모범 답안을 보여 주는 것까지만 한다

## 0. 시작 — 팀과 모드를 정한다

`$ARGUMENTS` 를 읽는다.

| 인자 | 뜻 |
|---|---|
| `01` | 네트워크 01 → 출제 범위 **C + D + A** |
| `02` | 네트워크 02 → 출제 범위 **C + D + N** |
| `실전` | 실전 모드 (아래 2절) |
| `오답` | 기록에서 2점 이하였던 문항만 다시 낸다 |
| 없음 | 기본은 연습 모드. 팀은 기록에서 찾고, 없으면 묻는다 |

팀을 모르면 이렇게 묻는다.

> "네트워크 01 팀입니까, 02 팀입니까? 01은 AI 네이티브 회사, 02는 네트워크 서비스 로드맵이 시험 범위에 들어갑니다."

그다음 `내학습/모의고사.md` 를 연다.

- **없으면** 아래 3절 형식으로 만든다
- **진행 중인 회차가 있으면** 이어서 할지 묻는다 → "지난번 {N}번 문제까지 풀었습니다. 이어서 할까요, 새 회차를 시작할까요?"
  이어서 하면 그 회차의 사례를 그대로 쓴다

### 사례 — 새 회차마다 바꾼다

문항과 개념 설명은 같고, 문제 속 사례만 다른 판이 네 개 있다. 같은 사례를 두 번 풀면 개념이 아니라 답을 기억해서 맞히게 된다.

| 순서 | 사례 | 문제 파일 | 채점 파일 |
|---|---|---|---|
| 1 | 장비 대여 | `문제.md` | `채점기준.md` |
| 2 | 동아리방 | `문제-동아리방.md` | `채점기준-동아리방.md` |
| 3 | 학식 | `문제-학식.md` | `채점기준-학식.md` |
| 4 | 스터디 | `문제-스터디.md` | `채점기준-스터디.md` |

- **새 회차를 시작하면** 기록에서 이 팀이 이미 쓴 사례를 보고, **아직 안 쓴 사례 중 순서가 가장 앞인 것** 을 고른다. 회차 제목에 `사례: …` 가 없는 옛 회차는 장비 대여로 본다
- 네 사례를 다 썼으면 학생에게 고르게 한다 → "네 사례를 모두 풀었습니다. 어느 사례로 다시 볼까요? 점수가 가장 낮았던 회차는 {사례}입니다."
- 학생이 사례를 직접 말하면 그것을 쓴다
- 한 회차 안에서는 문제와 채점을 **같은 사례 파일 짝** 으로만 한다. 다른 사례의 채점기준으로 채점하지 않는다

시작 전에 학생에게 이것만 알린다.

> "30문제, 문제당 5~12줄. 자료는 덮으세요. 개념 설명은 문제 안에 있습니다.
>  설명을 옮겨 적으면 점수가 없습니다. 왜 그런지, 이 사례에서는 어떻게 되는지를 쓰세요.
>  '모르겠다'도 답입니다. 지어내는 것보다 낫습니다."

## 1. 출제 순서 — 섞어서 낸다

시험장에서는 문제가 단원별로 안 나온다. 그래서 **세 영역을 번갈아** 낸다 (인터리빙).
아래 순서를 그대로 따른다. 이어 풀기가 가능하도록 순서는 고정이다. `X` 는 01팀이면 `A`, 02팀이면 `N` 이다.

```
 1 C1    2 D1    3 X1    4 C2    5 D2    6 X2
 7 C3    8 D3    9 X3   10 C4   11 D4   12 X4
13 C5   14 D5   15 X5   16 C6   17 D6   18 X6
19 C7   20 D7   21 X7   22 C8   23 D8   24 X8
25 C9   26 D9   27 X9   28 C10  29 D10  30 X10
```

문제를 낼 때는 이번 회차 사례의 문제 파일에서 **공통 설정** 을 1번 문제 전에 한 번 보여 주고,
이후에는 문항 본문(**개념 설명 + 질문**)을 그대로 보여 준다. 개념 설명을 빼거나 줄이지 않는다.
문항 앞에 `[7/30] C3 [적용]` 처럼 번호·유형을 붙인다.

## 2. 모드

### 연습 모드 (기본)

한 문제 → 학생 답 → **바로 채점** → 다음 문제.

### 실전 모드

**5문제를 연달아 낸다. 그동안 채점도, 반응도 하지 않는다.** 답을 받으면 "받았습니다" 한 마디 후 다음 문제.
5문제가 끝나면 한꺼번에 채점한다. 시험장처럼 피드백 없이 버티는 연습이다.

### 오답 모드

기록에서 **2점 이하** 문항만 1절 순서대로 다시 낸다. 다시 맞히면(3점) 기록의 상태를 `회복` 으로 바꾼다.
같은 문항을 **틀렸던 회차와 다른 사례** 로 낸다 (안 쓴 사례가 앞순위). 같은 사례로 다시 내면 지난번 모범 답안을 떠올려 맞힐 수 있다.
다시 낼 때는 그 사례의 공통 설정을 먼저 보여 준다. 기록의 비고에 `사례: {사례}` 를 남긴다.

### 힌트

학생이 힌트를 달라고 하면 **딱 하나** 만 준다. 그리고 기록에 `힌트` 를 남긴다.

- 줄 수 있는 힌트: **"이 문제는 {N}주차 / {로드맵} Phase {N} 범위입니다"** — 범위만 알려 준다
- 그 이상은 주지 않는다. 체크포인트 내용, 개념 이름, 강의 제목은 힌트가 아니라 답이다

## 3. 채점

학생 답이 오면 그때 **문제를 낸 사례의 채점기준 파일** 에서 **그 문항만** 읽는다.

### 순서

1. **체크포인트 3개를 하나씩** 판정한다. 각각 ✅ / ❌. 부분 점수 없음
   - 판정 근거로 **학생이 쓴 문장을 그대로 인용** 한다. 어디서 맞고 어디서 빠졌는지 본인이 보게 한다
   - **문제의 개념 설명을 되풀이한 문장은 ❌.** 설명에 있던 말이 아니라 설명에 없던 이유 · 적용 · 결과로 판정한다
   - "중요하다", "문제가 생긴다" 처럼 **무엇이 어떻게** 가 빠진 문장은 ❌. 장면이나 값이 있어야 한다
   - 계산 문항은 과정이 없으면 답이 맞아도 그 체크포인트는 ❌
2. **판정** 하나를 붙인다

   | 점수 | 판정 |
   |---|---|
   | 3 | **맞음** |
   | 1~2 | **부분** — 빠진 체크포인트를 짚는다 |
   | 답이 `함정 답` 에 해당 | **유창하지만 틀림** — 점수와 무관하게 붙인다. 가장 중요한 판정이다. 왜 그럴듯해 보이는지와 어디서 어긋나는지를 함께 말한다 |
   | 0 / 모르겠다 | **모름** |

3. **그다음에만** 모범 답안을 보여 준다. "하나의 예시"라고 밝힌다
4. 2점 이하면 **근거 강의** 를 알려 준다 → "이 강의를 다시 보세요. `/study` 로 해당 강의를 시험 볼 수 있습니다."
5. 3점이면 정교화 질문 **하나** 를 던져도 된다 (선택). 예: "그 기준이 깨지는 상황은 언제입니까?" 답은 점수에 넣지 않는다

### 채점 출력 형식

```
[10/30] C4 — 2/3  부분

✅ ① b를 골랐다 — "분실 원인이 기록 누락이 아니면 뭘 만들어도 소용없다"
✅ ② c를 골랐다 — "다크 모드는 없어도 서비스 목적은 그대로"
❌ ③ 사실/가정 — "확인한 것만 사실이므로 가정이다"는 설명을 옮긴 것이다. 사실로 옮기려면 무엇이 있어야 하는지가 없다

▶ 모범 답안(예시)
...

▶ 다시 볼 강의: 3주차 · 06 Creating Hypotheses about PMF
```

### 기록 — 문항마다 바로 쓴다

채점이 끝날 때마다 `내학습/모의고사.md` 에 한 줄 추가한다. 세션이 끊겨도 이어 풀 수 있어야 한다.

```markdown
# 중간고사 모의시험 기록

## 1회차 — 네트워크 02 — 사례: 장비 대여 — 2026-10-06 시작

| # | 문항 | 유형 | 점수 | 판정 | 비고 | 상태 |
|---|---|---|---|---|---|---|
| 1 | C1 | 이유 | 2/3 | 부분 | ② 쓰는 사람·결정하는 사람 충돌 예 없음 | |
| 2 | D1 | 적용 | 3/3 | 맞음 | | |
| 3 | N1 | 이유 | 1/3 | 유창하지만 틀림 | "방화벽 포트 막힘" — 목적지 IP와 bind 주소를 안 봄 | |
```

- 비고에는 **빠진 체크포인트를 한 줄로** 적는다. 다음에 오답 모드에서 이것만 보고도 무엇을 다시 볼지 알 수 있게
- `힌트`·`열람`(채점기준을 먼저 봄)은 비고에 적는다
- 상태 칸은 오답 모드에서 다시 맞히면 `회복` 으로 채운다
- 회차 제목에 **사례** 를 꼭 적는다. 다음 회차의 사례를 고를 때 이것을 본다

## 4. 끝낼 때

### 30문제를 다 풀었으면 — 성적표

기록 파일의 회차 아래에 성적표를 붙인다.

```markdown
### 성적표

| 영역 | 점수 | 맞음 / 부분 / 유창하지만 틀림 / 모름 |
|---|---|---|
| 공통 3~6주차 (C) | 22/30 | 5 / 4 / 1 / 0 |
| DB 설계 (D) | 18/30 | ... |
| 네트워크 서비스 (N) | 15/30 | ... |
| **합계** | **55/90** | |

| 유형 | 점수 |
|---|---|
| 이유 | 14/24 |
| 적용 | ... |
| 구별 | ... |

**가장 약한 것**: (가장 많이 빠진 체크포인트의 공통점을 한 문장으로)
**다음에 할 것**: (근거 강의 2~3개, `/study` 로)
**2단계**: `/midterm-prompt {팀}` — 같은 개념을 AI에게 시키는 문제
```

**유형별 점수를 꼭 낸다.** 유형마다 약점의 뜻이 다르다. 학생에게 이 차이를 직접 짚어 준다.

- [이유]만 낮다 → 규칙은 따라 하지만 **왜** 인지 모른다. 규칙이 안 맞는 상황에서 무너진다
- [적용]만 낮다 → 설명은 할 수 있는데 **처음 보는 사례** 에 대지 못한다. 예제를 더 풀어야 한다
- [구별]만 낮다 → 비슷한 개념을 **한 덩어리로** 알고 있다. 둘을 나란히 놓고 차이를 써 보게 한다

### 중간에 끝내도 — 마무리

1. 2점 이하 문항을 `내학습/복습큐.md` 에 넣는다. 형식은 `/study` 와 같다
   ```markdown
   | 장비 대여 ERD에서 시간 축을 빼면 N:M을 1:N으로 착각한다 (D3) | 중간고사 모의 · DB Phase 2 | 2026-10-06 | 2026-10-07 | 1회차 |
   ```
   항목 이름은 문항 번호가 아니라 **무엇을 놓쳤는지** 로 쓴다
2. `내학습/진행상황.md` 에 한 줄 남긴다 — 날짜, `중간고사 모의 {팀} {회차}회차 {시작}~{끝}번`, 점수 합계
3. **학생에게 요약을 시킨다.** 내가 요약하지 않는다
   > "오늘 틀린 문제들의 공통점을 한 문장으로 써 보세요. 설명은 읽었는데 무엇을 쓰지 못했습니까?"
4. 커밋을 권한다
   ```bash
   git add 내학습/ && git commit -m "학습: 중간고사 모의 {팀} {N}~{M}번"
   ```
5. **2단계를 안내한다.** 30문제를 다 풀었거나, 한 영역을 다 풀었으면
   > "다음은 2단계 `/midterm-prompt {팀}` 입니다. 오늘 맞힌 개념을 AI에게 시킬 수 있는지 봅니다.
   >  시험은 설명할 수 있는지가 아니라 AI에게 쓸 수 있는지까지 봅니다."
